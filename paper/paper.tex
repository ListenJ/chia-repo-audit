\begin{abstract}
As LLM agents increasingly generate RTL and make microarchitectural decisions,
the community lacks a verifiable benchmark for measuring whether such outputs
are correct and whether their performance claims generalize. We present an
\emph{agentic audit loop} built on the CHIA framework that applies a
double-blind annotation protocol—adapted from proven semantic-equivalence
evaluation ($\kappa{=}0.954$)—to systematically audit AI-generated hardware
designs for correctness, reproducibility, and evaluation fairness. Our loop
runs a standardized simulation across a pre-registered grid of seeds, prompts,
and traces, and emits a reproducibility scorecard including cross-seed
variance, prompt sensitivity, and inter-annotator agreement. We release the
loop, adversarial test cases, and raw logs as composable CHIA blocks.
\end{abstract}

\section{Introduction}
\label{sec:intro}

The Architecture 2.0 ecosystem—ArchAgent, CHIA~\cite{chia}, QuArch,
HLS-Eval—is expanding rapidly: LLM agents now generate RTL, discover cache
replacement policies, and make microarchitectural choices via simulation.
Our September 2026 scan did not identify a reusable audit harness that
systematically measures whether such outputs are correct or reproducible.

This gap is alarming given the 2026 benchmark-integrity crisis in the
software domain: the Meerkat audit~\cite{meerkat} found that all top-three
Terminal-Bench~2 submissions \emph{cheated} via harness-level vulnerabilities;
OpenAI deprecated SWE-bench Verified and retracted SWE-bench
Pro~\cite{reprocrisis}; and a systematic review of 168 benchmarks found
$>25.7\%$ have critical defects~\cite{autobench}. If software-side agent
evaluation is this fragile, \emph{hardware-side} agent outputs face at least
as severe reproducibility risks—yet no audit infrastructure exists.

We address this with an agentic audit loop (Figure~\ref{fig:loop}) that
adapts a proven double-blind annotation protocol ($\kappa{=}0.954$,
$\text{N}{=}100$) from semantic-equivalence evaluation to the hardware
design domain. The loop is creative: it is an \emph{agentic loop that audits
other agentic loops}, turning the hackathon's ``agentic architecture'' theme
into a measurable, publishable audit of agent trustworthiness.

\subsection{Stage 1: Prepare}
Pins the environment (git SHA, Python version, tool versions) as a
reproducibility anchor. Loads the pre-registered audit configuration:
metrics, acceptance thresholds, and error taxonomy. \textbf{All thresholds
are frozen before running} (pre-registration), preventing post-hoc
rationalization—a practice directly motivated by the contamination
literature~\cite{contamination}.

\subsection{Stage 2: Run}
Executes a simulation grid across $|\text{seeds}| \times |\text{prompts}|
\times |\text{traces}|$ cells, each repeated $n$ times. For each cell, the
loop invokes a simulator (currently a deterministic stub; on funded compute,
gem5/ChampSim via CHIA's built-in toolchain) and records cycle count, IPC,
and cache metrics.

\subsection{Stage 3: Double-Blind Audit}
\label{sec:dblind}

This is the core novelty. We adapt a double-blind annotation protocol
proven in semantic-equivalence evaluation ($\kappa{=}0.954$, 100 examples,
20\% re-audit sampling) to the hardware domain:

\vspace{-0.5em}
\centering\small
\begin{tabular}{cl}
\toprule
\textbf{Class} & \textbf{Description} \\
\midrule
E0 & Equivalent (correct design) \\
E1 & Parameter mislink (wrong value) \\
E2 & Direction error (e.g., LRU$\leftrightarrow$MRU) \\
E3 & Missing component \\
E4 & Added spurious component \\
\bottomrule
\end{tabular}
\vspace{0.3em}
\caption{Error taxonomy adapted from semantic-equivalence E1--E4.}
\label{tab:errors}
\end{table}

Two independent ``auditor agents'' (A, B) evaluate each candidate design
against its reference specification, classifying errors per Table~\ref{tab:errors}.
Disagreements are resolved by an arbitration agent. Inter-annotator
agreement is measured by Cohen's $\kappa$ (gate: $\kappa \geq 0.7$).
A 20\% re-audit sample detects gold-drift.

\subsection{Stage 4: Audit and Act}
Computes a reproducibility scorecard: strict/lenient equivalence rates,
$\kappa$, error-class distribution, repeated-run CV, cross-seed CV, prompt
spread, trace CV, and a \emph{publish gate} (BLOCKED if $\kappa < 0.7$ or if
adversarial cases are not all detected). Per the Meerkat lesson: scores from
an unaudited harness must not be published.

\section{Experimental Setup}
\label{sec:setup}

\textbf{Framework:} CHIA (BSD-3-Clause) with built-in Chipyard, gem5,
ChampSim, Verilator, Spike. \\
\textbf{Pre-registered metrics:} cross-seed CV $< 5\%$ = reproducible;
prompt sensitivity = cycle-count spread ratio; trace-subset CV. \\
\textbf{Adversarial cases:} 5 pre-planted known-bad designs (E1--E4 $+$ a
``always-passes'' weak-verifier trap) to test whether the audit catches them. \\
\textbf{Gold standard:} 5 pre-planted known-good/bad designs for calibration. \\
\textbf{Compute:} short-term funded GCP/Gemini credits (Sep 21--23).

\section{Results}
\label{sec:results}

\textbf{Stub validation (loop's own outputs, config v5).} The pipeline maps
each generation seed and prompt to a concrete candidate artifact, runs that
candidate across the trace grid, and emits a scorecard with the
pre-registered metrics:
\begin{itemize}\setlength{\itemsep}{0pt}
\item \textbf{Reproducibility.} Cross-seed coefficient of variation $= 3.65\%$
(below the pre-registered $5\%$ threshold) $\rightarrow$ \textsc{Reproducible};
repeated-run CV $= 0.20\%$, and trace CV $= 0.24\%$. Prompt spread across
CoT/adversarial prompt variants $= 0.79\%$, trace top-1 stability $= 1.00$,
and mean leave-one-trace-out Kendall $\tau = 1.00$. These values validate the
candidate-to-simulation plumbing and ranking analysis; the default candidate
catalog is a fixture, not real LLM output.
\item \textbf{Double-blind audit.} Both auditor agents classify all 10
calibration/adversarial cases correctly: gold calibration $5/5$, adversarial
detection $100\%$, error distribution E1$=2$, E2$=2$, E3$=2$, E4$=3$.
Inter-annotator agreement $\kappa{=}1.0$ reflects the \emph{deterministic}
stub auditors (protocol-logic self-test); the protocol \emph{provenance} is
the Axiom semantic-equivalence run ($\kappa{=}0.954$, human annotators,
$N{=}100$). Publish gate: \textsc{PASS}.
\end{itemize}

\textbf{Pinned source-build smoke.} Before funded execution, we built CHIA's
pinned DPC4-ChampSim revision (\texttt{164fdb1e...}) on a generic Linux host
and ran the upstream smoke trace twice. Both runs retired 5,003 instructions
in 40,459 cycles (IPC 0.123656) with identical parsed metrics. This validates
the source build, trace resolution, parser, and repeated-run stability. It is
a smoke check, not a performance benchmark and not yet a CHIA Docker/Ray
result.

\subsection{Artifact \& Reproducibility}
The loop (\texttt{chia\_loop/loops/audit\_repro.py}), adversarial cases
(\texttt{av-001..005}), gold standard (\texttt{gold-01..05} +
\texttt{answer-key}), and raw logs are released as composable CHIA blocks
(BSD-3-Clause). To reproduce the stub validation:
\texttt{python3 chia\_loop/loops/audit\_repro.py --version 5}; outputs land
in \texttt{results/} (scorecard, raw, dblind report) with the pinned git SHA
and Python version. The public artifact also includes
\texttt{scripts/kaggle\_champsim\_smoke.py} and the machine-readable
\texttt{results/kaggle\_champsim\_smoke\_result.json}. The official
image-level path still requires the pending smoke run described above. Per the
publish-gate rule, scores are released only when the audit gate passes. The
artifact is available at \url{https://github.com/ListenJ/chia-repo-audit}.

\section{Discussion}
\label{sec:discuss}

\textbf{Why double-blind?} Single-annotator evaluation is vulnerable to
the same failure mode that corrupted Terminal-Bench~2: the evaluator and
the generator share a scaffold, creating circular trust. Double-blind
annotation with $\kappa$ quantification breaks this circularity.

\textbf{Composability.} The loop, adversarial cases, gold standard, and
raw logs are released as composable CHIA blocks. Other teams can reuse
the audit protocol for their own agentic architecture loops—turning
reproducibility auditing from an afterthought into a first-class,
reusable infrastructure component.

\textbf{Self-audit case: the gate caught our own blind spot.} During
development, the stub auditors were intentionally asymmetric: one auditor
treated design keys prefixed \texttt{extra\_} as non-reportable, modeling
annotator variation. Under that configuration the audit achieved only $60\%$
adversarial detection and the publish gate returned \textsc{Blocked}—it
missed E4 (spurious component) on cases \texttt{gold-02} and \texttt{av-004}.
This is the audit working as intended: the same blind spot a human panel
would carry silently was surfaced as a gate failure. Reverting to strict,
symmetric auditors raised detection to $100\%$ (gold $5/5$) and the gate to
\textsc{Pass}. We report the negative intermediate result deliberately: a
double-blind audit's value is precisely that it can catch the evaluator's own
confirmation bias before scores are published.

\textbf{Limitations.} The stub simulator injects synthetic noise; real
ChampSim results may differ. The error taxonomy (E0--E4) is adapted from NLP
and may not cover all hardware-specific failure modes. Our $\kappa{=}1.0$ is
from \emph{deterministic} stub auditors (protocol self-test) and is not a
human inter-rater estimate; the $\kappa{=}0.954$ is the provenance of the
source protocol (Axiom semantic-equivalence), and a true inter-rater $\kappa$
must be measured with actual annotators in deployment.

The current seed and prompt axes select among fixture candidates rather than
querying an LLM. Directory mode is the integration point for real generated
candidates, but it has not yet been populated by an agent run. Trace CV is a
diagnostic over cycle counts; the separate top-1 and Kendall-tau metrics
measure ranking stability under trace removal.

\section{Conclusion}
We present an agentic audit loop and a pre-registered pilot for measuring the
reproducibility and correctness of architecture-search outputs. The loop is
composable, the methodology is explicit, and the stub validation confirms the
pipeline end-to-end: repeatability and sensitivity metrics, adversarial
detection, and a publish gate that blocks unaudited scores. Real ChampSim
evidence and actual candidate-generation axes remain future work for this
artifact revision.
